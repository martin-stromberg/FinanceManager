# Release Notes

## Important Notes Before Update

- The update adds the database check constraint `CK_Postings_HasReference`: every posting must reference an account, contact, savings plan or security. If an existing database contained postings without any reference, the migration — and thus the app start — would fail deliberately; such rows cannot be produced by the application, but should the update abort for this reason, the orphaned postings must be removed manually first (issue #497).
- New opt-in feature: the MCP server (`/mcp`) lets external AI assistants access the owner's financial data through scoped, audited tools. It ships **disabled by default** — an administrator enables it anytime in the admin security settings (`/card/mcp-security`, database-stored `Enabled`/`WriteAccessEnabled` switches). Existing installations keep working unchanged.
- The MCP settings are stored in the database, not in `appsettings.json`; write access has a separate opt-in kill switch so an admin can enable read-only MCP access first.

- Security hardening: forwarded headers (`X-Forwarded-For`/`X-Forwarded-Proto`) are now only honored from explicitly trusted proxies. If FinanceManager runs behind a reverse proxy, list its IPs in `ReverseProxy:KnownProxies` and/or its subnets in `ReverseProxy:KnownNetworks` (semicolon-separated). Without these entries the app ignores forwarded headers — client IPs would then appear as the proxy's address. Direct HTTP access in local networks keeps working unchanged.
- Self-registration is now opt-in: only the very first user can register themselves; additional accounts are created by an administrator. Set `Auth:AllowSelfRegistration` to `true` to re-enable open registration.
- Security hardening: session cookies are marked `Secure` when the app is served via HTTPS (including TLS-terminating reverse proxies via forwarded headers). If the app is exposed to untrusted networks, serving it via HTTPS is strongly recommended.

## What's New

- New "Depot development year-over-year" tile in the portfolio analysis report (`/portfolio/analysis-report`): combined line/bar chart of the year-end (Dec 31) portfolio value and net dividends per year, a yearly table with changes and yield, a period filter (full history / last 5 / last 10 years), a switchable yield basis (year-start value or invested capital = yield on cost), a "*" marker for the running year (YTD) and automatic visibility for existing users (issue #512).
- Reports: amount cells in the report dashboard now offer a drill-down — a symbol button on amount, previous-period and previous-year cells opens an overlay listing the postings behind the figure (date, source, description, amount) with the total sum (issue #510).
- Reports: the filter dialog gains free-text filters per posting type — any number of OR-linked, case-insensitive substring entries matching purpose and description, persisted in report favorites and applied to the home KPI tiles (issue #506).
- Bugfix: on the posting detail card the five "Linked Information" ribbon actions now work — Open Account/Contact/Savings Plan/Security navigate to the linked record's card (with return navigation to the posting), and Attachments opens the posting's attachments overlay; the actions stay disabled when the respective link is missing or no posting is loaded (issue #502).
- Ribbon: the "Linked Information" group is now the last group on the savings-plan, bank-account and posting detail cards; the settings page leads with "Manage" and shows Save as the large primary action, and the contacts overview uses the "Manage" group with large actions (issue #498).
- Data-integrity hardening: a posting must now reference at least one target (account, contact, savings plan or security) — enforced by a domain guard and the database check constraint `CK_Postings_HasReference`; backup imports skip postings whose references cannot be remapped, and the intentionally user-independent data pools (`IpBlock`, `SecurityTxtSettings`, `WellKnownSettings`, `McpSettings`) are now documented explicitly as global (issue #497).
- Bugfix: the backup restore no longer loses data — statement imports/entries, notifications, account shares, linked IBANs and portfolio KPI configurations are now re-imported (previously exported but never restored); the backup DTOs were completed (budget rules, securities) and the merge import tolerates duplicates (issue #496).
- Savings plans: removing an account link now asks for confirmation first. MCP: `fm_savings_plan_analysis` reports each plan's `linkedAccountIds`, and `fm_savings_plans_manage` link operations return the current `linkedAccountIds` — linked plans keep reporting the account-balance-based `accumulatedAmount`.
- Savings plans: account links can now only target savings accounts (service-enforced); the linked-accounts panel gains an info button explaining the link's purpose, icon buttons for unlinking and opening an account, a per-account balance column when multiple accounts are linked, and a new "own share" (Eigenanteil) figure in the plan header showing the plan's own posting balance while the saldo follows the linked account balances.
- Reports: new setting "savings plan posting source" lets a report choose whether emitted savings plans aggregate their own plan postings or the postings of their linked bank accounts (available when savings plans are selected; persisted in report favorites, `fm_reports_configuration_manage`/`fm_reporting_aggregate`).
- Demo data: new Bauspar scenario — savings account "Bausparkonto" linked to plan "Bausparen" with monthly giro transfers, 1% year-end interest on giro and Bauspar balances, a monthly deposit budget and a "Sparplanbuchungen (monatlich)" report favorite.
- Savings plans: bank accounts can now be linked to a plan in the plan details (linked-accounts section) — a linked plan derives its accumulated amount from the linked account balances and its rhythm analysis from the account inflow; funding postings of linked plans are marked as informal in posting lists and details and no longer count into the plan's accumulated/expected amounts. Plans without links gain an "Istmeldung" (actual-balance report) action that corrects the plan balance via a difference posting without an account movement. MCP: `fm_savings_plans_manage` gains `addAccountLink`/`removeAccountLink`/`reportActualBalance` operations.
- Savings plans: new persistence for explicit many-to-many links between a savings plan and bank accounts (unique plan/account pairs, owner-scoped, multiple accounts per plan and multiple plans per account supported) — groundwork for upcoming account-based savings tracking; no user-facing function yet.
- MCP integration: personal access tokens (`fm_mcp_*`) with five access levels, fine-grained scopes and filters, a persistent approval queue with approval-center UI, hash-chained audit trail with integrity verification and export, SSE status notifications, and 38 tools across four security classes — including owner-admin-gated `fm_admin_*` tools (installation status, updates, backups incl. ticketed download and restore) — documented under Help → MCP-Server.
- MCP: new account type `CreditCard` marks a credit-card settlement account — its statement drafts can only be booked indirectly as a split of a parent giro statement entry (never standalone); `fm_statement_draft_edit` gains an `assignAccount` operation (assigns/overwrites the draft's detected account and re-runs classification), and `fm_statement_drafts_read` exposes the draft's original statement file (`sourceAttachment`, readable via `fm_attachments_read`).
- MCP: `fm_reporting_aggregate` gains an optional `year` filter and a `coverage` result field that states the covered time span explicitly (the `Ytd` interval produces year-to-date buckets across all calendar years, not just the current one); the hash-chained audit trail tolerates concurrently written entries via bounded re-anchoring on sequence collisions.
- MCP: `fm_savings_plan_analysis` now reports the deposit backlog against the plan's own observed contribution rhythm — `scheduleDeficit`/`expectedToDate`/`receivedToDate`/`observedMonthlyRate` show whether scheduled deposits were missed (a positive deficit means missed deposit(s)), while extraordinary withdrawals are listed separately as `disbursements` and reversal pairs are excluded from both sides; plans without a detectable rhythm return `null` for the rhythm fields.
- MCP: `fm_savings_plan_analysis` — `scheduleDeficit` is now cycle-based and counts only the current financing cycle since the last due disbursement (≈ targetAmount, else the largest withdrawal, else the last reached targetDate, else the first deposit), so completed cycles no longer inflate the backlog; revolving plans whose disbursements balance their deposits report `null` (cyclically balanced).
- MCP: `fm_savings_plan_analysis` — the rhythm fields now derive from the dominant amount class of the cycle's deposits (most frequent recurring amount, ties by larger amount) instead of a median over monthly totals: micro postings such as interest credits (below ~50% of the dominant class amount) no longer dilute `observedMonthlyRate`/`expectedToDate`/`receivedToDate`, so a missed deposit month surfaces as the deficit it is.
- MCP: `fm_savings_plan_analysis` — `observedMonthlyRate` and `expectedToDate` now follow the deposit cadence observed in the postings (median month gap between the dominant class's booking months) instead of the plan interval, which marks the expense's due rhythm rather than the deposit cadence: monthly deposits funding an annual fee (e.g. an ADAC membership) now report the monthly rate instead of a twelfth of it; the plan `interval` only serves as fallback when no cadence is derivable (fewer than two booking months).

## Wichtige Hinweise vor dem Update

- Das Update führt den Datenbank-Check-Constraint `CK_Postings_HasReference` ein: Jede Buchung muss ein Konto, einen Kontakt, einen Sparplan oder ein Wertpapier referenzieren. Enthielte eine Bestandsdatenbank Buchungen ganz ohne Referenz, würde die Migration — und damit der App-Start — bewusst fehlschlagen; die Anwendung kann solche Zeilen nicht erzeugen, sollte das Update dennoch daran scheitern, sind die verwaisten Buchungen zuvor manuell zu entfernen (Issue #497).
- Neue Opt-in-Funktion: Der MCP-Server (`/mcp`) gibt externen KI-Assistenten über abgestufte, protokollierte Werkzeuge Zugriff auf die Finanzdaten des jeweiligen Besitzers. Er ist **standardmäßig deaktiviert** — ein Administrator aktiviert ihn jederzeit in den Admin-Sicherheitseinstellungen (`/card/mcp-security`, datenbankgestützte Schalter `Enabled`/`WriteAccessEnabled`). Bestehende Installationen bleiben unverändert funktionsfähig.
- Die MCP-Einstellungen liegen in der Datenbank, nicht in `appsettings.json`; der Schreibzugriff hat einen eigenen Opt-in-Schalter, sodass zunächst reiner Lesezugriff freigegeben werden kann.
- Sicherheitshärtung: Forwarded-Headers (`X-Forwarded-For`/`X-Forwarded-Proto`) werden nur noch von ausdrücklich vertrauenswürdigen Proxies berücksichtigt. Wird FinanceManager hinter einem Reverse-Proxy betrieben, sind dessen IPs unter `ReverseProxy:KnownProxies` bzw. dessen Subnetze unter `ReverseProxy:KnownNetworks` einzutragen (semikolongetrennt). Ohne diese Einträge ignoriert die Anwendung Forwarded-Headers — Client-IPs erscheinen dann als Adresse des Proxys. Direkter HTTP-Zugriff im lokalen Netzwerk funktioniert unverändert.
- Die Selbstregistrierung ist jetzt opt-in: Nur der allererste Benutzer kann sich selbst registrieren; weitere Konten legt ein Administrator an. `Auth:AllowSelfRegistration` auf `true` öffnet die Registrierung wieder.
- Sicherheitshärtung: Sitzungs-Cookies werden bei Bereitstellung über HTTPS als `Secure` markiert (inkl. TLS-terminierender Reverse-Proxies via Forwarded Headers). Bei Exposition gegenüber nicht vertrauenswürdigen Netzen wird HTTPS dringend empfohlen.

- Neue Statistik „Umkehrsignale" auf der Wertpapierkarte: erkennt Todeskreuz (mit Kreuzungsdatum), Brüche der 200-Tage-Linie (kurzfristige Schwäche vs. strukturelle Trendwende), bärische Marktstruktur, bärisches MACD-Crossover und RSI-Divergenz und fasst sie zu einem Trendstatus zusammen („Trend intakt" / „Trend geschwächt" / „Trendwende wahrscheinlich") (Issue #406).
- Neue Startseiten-Benachrichtigungen, wenn sich der Trendstatus eines Wertpapiers verschlechtert; pro Benutzer über eine neue Checkbox im Setup-Tab „Benachrichtigungen" abschaltbar.
- Behoben: Einstellungsseite — die Schaltfläche „Speichern" aktiviert sich jetzt bei Änderungen in allen Feldern der Sektionen „Kontoauszüge" und „Renditeanalyse" und deaktiviert sich wieder, sobald der gespeicherte Wert wiederhergestellt ist (Issue #431).
- Behoben: ING-CSV-Kontoauszüge können wieder importiert werden — das neue Exportlayout mit zusätzlicher Spalte „Referenz" wird unterstützt; ältere Exporte bleiben lesbar.
- Massenimport-Prüfdialog: nicht importierbare Dateien werden jetzt mit Grund angezeigt; die Warnung „Die Aktion kann nicht rückgängig gemacht werden." erscheint nur noch, wenn mindestens eine Datei tatsächlich importiert wird.
- Behoben: Anhänge lassen sich wieder löschen — der Lösch-Bestätigungsdialog wurde zuvor vom geöffneten Anhang-Overlay verdeckt.
- Neuer öffentlicher Endpunkt `/.well-known/change-password` (W3C Well-Known): leitet per HTTP 302 auf die konfigurierte Passwort-ändern-Seite weiter — Standard-Auffindadresse für Browser und Passwortmanager.
- Neue Self-Service-Seite `/change-password`: Angemeldete Nutzer können ihr eigenes Passwort ändern (aktuelles und neues Passwort); bisher war nur ein Admin-Reset möglich.
- Neue Sektion „Well-Known" im Setup-Bereich: Administratoren können die Ziel-URL der Weiterleitung konfigurieren (lokaler Pfad oder externe http/https-URL, Standard `/change-password`).
